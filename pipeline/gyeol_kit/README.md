## 0. 한 줄

**내보낸 파일 → 주 단위 지표 → 직전 52주와 비교 → 인출 필터 → `gyeol_data.json`**

전 구간이 로컬에서 돕니다. **원본은 사용자 기기를 떠나지 않습니다.**

## 1. 실행

```bash
cd ~/Desktop/gyeol_kit
python3 run_gyeol.py
```

`data/` 안에 내보낸 파일을 넣어두면 `gyeol_data.json`이 나옵니다.
파이썬 표준 라이브러리 위주이고, 외부 의존이 거의 없습니다.

### 넣는 파일

| 채널 | 파일 | 파서 |
|---|---|---|
| 건강 (걸음·수면·운동) | 애플헬스 `내보내기.zip` | `parse_health.py` · `shrink_health.py` |
| 유튜브 (심야·검색) | Takeout `watch-history.json` `search-history.json` | `parse_takeout.py` |
| 사진 | Takeout Google 포토 / EXIF | `parse_photos.py` |
| 캘린더 | Takeout `.ics` | `parse_takeout.py` |
| 카카오톡 | 대화 내보내기 `.txt` | `parse_kakao.py` |
| 메모 | `my_notes_text.tsv` | `parse_notes.py` · `sanitize_notes.py` |
| AI 대화 | `conversations.json` | `parse_ai.py` **(미반영)** |

## 2. 단계

### ① 수집 → ② 주 단위 집계
`channels.py` · `feature_extractor.py`
일별 기록을 **ISO 주차**로 묶어 16개 지표를 만듭니다.
지표: 걸음수 · 수면시간 · 메모 작성수/길이/심야비율 · 사진 촬영수/심야비율 · 일정 개수 · 유튜브 심야비율/검색량 …

### ③ 판정 — `rolling_baseline.py` · `judge.py`

| 규칙 | 왜 |
|---|---|
| **직전 52주와만 비교** | 유튜브 사용량이 12년간 150배 늘었습니다. 전체 평균과 비교하니 "많이 쓰게 된 것"을 "상태가 변한 것"으로 오독했습니다 (v4) |
| **백분위, z-score 아님** | 새벽 발화 지표의 88%가 정확히 0인 분포입니다 (v3) |
| **대기 4주 + 지속 4주** | 첫 버전이 가족 장례 주를 "1주 만에 회복"으로 판정했습니다. 그다음 주 평균 수면이 1.6시간이었습니다 (v1) |
| **출처 계열 단위로 증거를 셈** | 같은 로그에서 뽑은 지표 5개는 증거 5개가 아니라 **1개**입니다 (v5) |

### ④ 인출 필터 — `crisis_filter.py`
자동 노출 / 확인 후 열람으로 나눕니다. **위기 점수는 저장하지 않습니다** — 저장하는 순간 건강 민감정보가 됩니다.

**v6 개정**: 봉인하지 않습니다. 말수를 줄입니다.
두드러진 주도 접근 가능하고, 지층 진입 시 **한 번만** 확인합니다. 회복 서사는 붙이지 않습니다.

### ⑤ 내보내기 — `export_app_data.py`
`gyeol_data.json` 생성. 앱은 이 파일 하나만 읽습니다.

## 3. ⚠ 지금 반드시 알아야 할 것 — 후처리가 파이프라인 밖에 있습니다

**`export_app_data.py`의 출력만으로는 현재 배포 파일과 같은 상태가 나오지 않습니다.**
아래 세 스크립트를 순서대로 더 돌려야 합니다.

| 순서 | 스크립트 | 하는 일 |
|---|---|---|
| 1 | `apply_principles.py` | v6 적용 — 봉인 해제 · **회복 서사 제거** · 접근 등급 재계산 |
| 2 | `add_relics.py` (`build_relics.py`) | 그때 쓴 글 부착. 문장다움 점수로 선별 |
| 3 | `pin_demo_relics.py` | 데모용 주의 원문 순석 고정 (선택) |

> **이게 현재 가장 큰 기술 부채입니다.**
> 다음 사람이 파이프라인만 돌리면 v5 상태가 나오고, 회복 서사가 살아 있고, 원문이 비어 있습니다.
> **후처리 3개를 `run_gyeol.py`에 흡수하는 것이 발표 후 1순위입니다.**

### 알려진 불일치 2건

| | 내용 |
|---|---|
| 1 | `export_app_data.py`가 `crisis_filter.split()`으로 제외된 주를 JSON에 **넣지 않습니다.** v6 개정대로면 `access:'confirm'`을 달아 내보내야 합니다. (현재 배포 파일은 후처리로 해결돼 있습니다) |
| 2 | `--limit 40` 기본값. 현재 배포 파일은 80주입니다. 발표에서 "10년"을 말할 때 **보유 데이터와 표시 주 수를 구분**해서 말해야 합니다 |

## 4. 메모 위생 필터 — `sanitize_notes.py`

**지표는 무해하지만 원문은 아닙니다.**
"그 주에 메모가 많았다"는 아무것도 노출하지 않지만, 그 주에 쓴 글을 그대로 돌려주면 **돌려주면 안 되는 것도 같이 돌아갑니다.**

실측: 메모 1,301개 중 **177개 제거**. 그 안에 실제 자격증명 **12건**(비밀번호·주민번호·계좌번호·OTP·CVC·토큰).

**순서가 중요합니다** — URL·전화번호·이메일을 **먼저 마스킹**한 뒤 키워드를 검사합니다.
반대로 하면 링크 안의 숫자를 계좌번호로 오판합니다 (v1에서 좋은 메모 9개를 잘못 버렸습니다).
