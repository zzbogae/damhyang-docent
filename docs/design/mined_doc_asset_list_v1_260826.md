## A. 먼저 고칠 것 — 원칙과 어긋난 항목 3

### A-1. ⚠ **「랜덤 광석 9종」** — 세 항목 전부

| 코드 | 현재 이름 |
|---|---|
| AP_RJewl_ui_concept_001 | **랜덤** 광석 9종 컨셉 |
| AP_RJewl_ui_image_001 | **랜덤** 광석 9종 UI 이미지 |
| AP_RJewl_3d_mod_001 | **랜덤** 광석 9종 3d 모델링 |

**세 가지가 동시에 어긋납니다.**

1. **「랜덤」** — 절대 원칙 3번이 랜덤뽑기 금지입니다. 그리고 코어는 `core_generator.py`가 **주간 데이터에서 규칙으로 그립니다.** 같은 데이터를 넣으면 언제나 같은 코어가 나옵니다. 발표에서 쓰는 문장이 "AI가 만든 게 아니라 계산된 무늬"인데, 에셋 이름이 「랜덤」이면 그 자리에서 무너집니다.
2. **「9종」** — 세계관설계서는 **광물 4종**입니다. 흑요석 · 자수정 · 청금석 · 호박. 9가 어디서 나온 숫자인지 확인이 필요합니다.
3. **「UI 이미지」로 만드는 것** — 코어 겉면은 4종이지만 **단면의 결은 주마다 다릅니다.** 이건 그려서 넣는 이미지가 아니라 코드가 그리는 SVG입니다. 미리 9장 그려두면 "이번 주 코어"가 아니라 "9장 중 하나"가 됩니다.

**제안 — 항목을 셋으로 쪼갭니다.**

| 새 코드 | 이름 | 성격 |
|---|---|---|
| `AP_core_ui_type_001` | **코어 겉면 4종** (흑요석·자수정·청금석·호박) | 그리는 에셋 ✅ |
| `AP_core_gen_rule_001` | **코어 단면 생성 규칙서** (결 두께·간격·색 파라미터) | 문서. 유단희 → 개발 전달 |
| `VR_core_3d_mod_001` | **코어 4종 3D 모델** | 부스용. 겉면만 |

> 3D는 필요합니다. 부스에서 손으로 집는 물건이니까요. 다만 **9종이 아니라 4종**입니다.

## E. 아이디어 5

### E-1. 광석은 「그리는 것」이 아니라 「계산되는 것」 — 시트 항목 성격을 바꿉니다
UI 이미지 9장을 그려두면 사용자는 9장 중 하나를 받습니다. 그러면 **"내 데이터가 무늬가 됐다"가 거짓말이 됩니다.**
유단희님이 만들 것은 이미지가 아니라 **생성 규칙서** — 결의 두께가 무엇에 대응하고, 간격이 무엇에 대응하는가. 그걸 넘기면 코드가 매주 다른 코어를 그립니다. **작업량은 줄고 개념은 강해집니다.**

### E-2. 발자국이 「빈 사용자」 문제를 풉니다
데이터가 적으면 코어가 없고, 코어가 없으면 화면이 빕니다. 세희님 케이스가 그거였습니다.
**발자국은 데이터가 없어도 쌓입니다.** 앱을 연 것만으로 생기니까요. 그래서 발자국은 장식이 아니라 **빈 상태를 메우는 유일한 장치**입니다. P1이 아니라 P0로 올릴 근거가 됩니다.

### E-3. 코어 카드 내보내기 = 아웃풋 한 줄의 답
8/19에 보경님이 「아웃풋이 없다」고 지목하신 자리에 넣을 수 있는 가장 싼 답입니다. 코어 이미지 + 사실 한 줄 + 날짜를 카드로 내보내기. **부스 출력물(BT_out_print_card_001)과 같은 에셋을 씁니다.** 하나 만들어 둘 다 씁니다.

### E-4. 색 의미는 「비워두는 것」이 답입니다
시트 비고의 "대표 색상별 의미 결정"을 지우고 **"의미는 사용자가 고름 — 앱은 정하지 않음"**으로 바꾸면, 미해결 안건 하나가 결정으로 닫힙니다. 그리고 그게 다른 앱과의 차별점 문장이 됩니다.

### E-5. 일정에 11월 마일스톤을 만듭니다
