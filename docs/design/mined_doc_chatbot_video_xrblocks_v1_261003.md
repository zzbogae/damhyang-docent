# Mine D 개인화 챗봇 → 데모 영상 → XR Blocks 설계안

## 한 문장

Mine D의 개인화 챗봇 **민디**는 기록을 대신 해석하거나 판정하지 않고, 기기 안에서 만들어진 광석의 근거를 보여준 뒤 사용자가 직접 말한 바람을 구조화된 **섬 설계도**로 바꾼다. 이 설계도만 이미지·영상 생성기에 전달하고, 승인된 결과를 XR Blocks의 상호작용 섬으로 연결한다.

## 사용자가 이해하는 흐름

`기록 → 지층·광석 → 민디와 대화 → 사용자가 바람 확정 → 섬 설계도 → 키 이미지 → 컷 영상 → 사람 검수 → XR 섬`

1. 사진·메모·캘린더 등의 원문은 기기 안에서 주간 특징으로만 계산한다.
2. 평소 범위를 벗어난 주가 광석이 되고, 지층의 해당 시점에 놓인다.
3. 사용자가 광석을 누르면 민디가 “그 주에 실제로 확인되는 사실”과 단어 칩을 보여준다.
4. 민디는 “어떤 공간에서 무엇을 하고 싶은가?”처럼 장면을 구체화하는 질문을 한다.
5. 사용자가 “노을 진 바다에서 맥주를 마시고, 물속에서 복어에게 조개를 건네고 싶다”처럼 자기 말로 확정한다.
6. 민디는 이를 생성기가 읽을 수 있는 섬 설계도로 변환하고, 사용자가 마지막으로 확인한다.
7. 승인된 설계도로 START/END 이미지와 영상을 생성한다.
8. 해부학·물리·연속성·오디오 검수를 통과한 결과만 섬의 장면으로 등록한다.
9. XR Blocks에서 광석을 선택하면 해당 섬과 영상·오브젝트가 열린다.

## 현재 구현 증거

- `MineD_Web_Demo_Safe/actual_demo.html`: 기존 Mine D 웹시연 원본을 복사한 실행본. 실제로 80주 지층, 광석 3회 채굴, 특정 주의 계산 근거, 민디 질문 화면을 Chrome에서 재검증했다.
- `MineD_Web_Demo_Safe/screenshots/`: 발표에 사용한 실제 조작 화면. 컨셉 목업이 아니다.
- `MineD_video_assets_v1/`: 10컷 START/END와 해부학·물리 게이트. C01은 v2, C07은 다리 오류를 고친 v2만 사용한다.
- `MineD_XRBlocks_v1/`: XR Blocks 0.21.1 데스크톱 시뮬레이터에서 광석 선택 → 섬 생성까지 검증한 최소 수직 슬라이스.

## GitHub 기억 아키텍처와의 연결

연동된 공개 저장소 [`inureyes/gyeol`](https://github.com/inureyes/gyeol)은 Mine D 웹앱 자체가 아니라, 개인화 AI의 장기 기억층으로 연결할 수 있는 기술 기반이다.

- `episodes`: 대화와 작업에서 남은 사건·결정·열린 질문
- `semantics`: 외부 자료와 주제별 통합 지식
- `bonds`: 사람·도구와의 관계에서 축적된 관찰
- `reflections`: 에피소드의 패턴을 성찰하고 `SELF.md`에 반영
- 보존 흐름: `Experience → Recording → Consolidation → Reflection → Identity`

Mine D에서는 원문 데이터와 주간 특징을 기존 로컬 저장소가 담당하고, gyeol식 기억 구조는 **민디가 이전 대화의 확정 선호·금지·결정 이유를 세션을 넘어 이어가는 층**으로 사용한다. 두 체계를 섞지 않고 `local_feature_id`와 사용자 승인 이벤트만 참조한다.

Slack 자료는 이 실행 환경에서 직접 읽는 커넥터가 노출되지 않았고, 프로젝트 폴더에서도 Slack 내보내기 파일을 찾지 못했다. 따라서 이번 정본에는 Slack 내용을 추정해 넣지 않았다. 연결이 노출되면 회의 결정과 실행 이력을 `episodes`로 수집하되, Drive 정본과 충돌하면 `NOW.md`를 우선한다.

## 개인화 챗봇의 AI 기능

| 기능 | AI가 하는 일 | AI가 하지 않는 일 |
|---|---|---|
| 근거 검색 | 로컬 특징과 광석 근거 중 현재 대화에 필요한 사실을 찾는다 | 원문 전체를 외부 서버로 보내지 않는다 |
| 기억 | 사용자가 확정한 선호·금지·스타일만 저장한다 | 추측한 성격이나 진단을 사실처럼 저장하지 않는다 |
| 대화 | 모호한 바람을 공간·행동·감각·관계 질문으로 구체화한다 | 욕구의 의미를 대신 결론 내리지 않는다 |
| 설계 | 사용자 문장을 장면 JSON과 컷 목록으로 구조화한다 | 승인 없이 외부 생성 비용을 쓰지 않는다 |
| 검수 보조 | 신체 수, 접촉점, 카메라 축, 음향 조건을 체크리스트로 만든다 | 생성 결과를 자동으로 최종 승인하지 않는다 |

개인화의 핵심은 “사용자의 모든 원문을 많이 보내는 것”이 아니라, **로컬 특징 + 사용자가 승인한 선택 이력 + 이번 대화의 확정 문장**이다.

## 영상 생성 오케스트레이션

1. **정책 게이트:** 여성 주인공, 같은 신체, 금지 표현, 원문 미포함을 검사한다.
2. **이미지 게이트:** 각 컷의 START/END를 만들고 사지 수·접촉점·톤을 검사한다.
3. **비용 게이트:** 모델, 길이, 해상도, 예상 비용, 남은 잔액, 총상한을 기록한다.
4. **생성:** Kling MCP에 컷당 한 번만 제출한다.
5. **대기:** `QUEUING/RUNNING`이면 재제출하지 않는다.
6. **검수:** 정상속도 전체 재생, 시작·중간·끝 프레임, 오디오를 확인한다.
7. **폴백:** 명확한 실패가 확인된 컷만 Higgsfield 견적 후 한 번 생성한다.
8. **등록:** 승인된 영상 URL/파일과 장면 메타데이터만 섬 자산 레지스트리에 넣는다.

## XR Blocks 연결

XR Blocks는 영상을 생성하는 도구가 아니라, **생성된 섬을 들어가고 선택하고 반응시키는 실행층**이다.

| 섬 설계도 필드 | XR Blocks 표현 |
|---|---|
| `island_id` | 월드 상태와 자산 묶음의 키 |
| 광석의 축·방향 | 광석 색·재질·발광 |
| `shots[]` | 공간 안 영상 패널, 포털 또는 장면 전환 |
| 행동 키워드 | 선택 가능한 오브젝트와 상호작용 이벤트 |
| 분위기 파라미터 | 조명·안개·환경음·색온도 |
| 사용자 선택 | 로컬 상태의 다음 섬 갱신 신호 |

### 실제 데모에서 증명한 것

- Chrome 데스크톱 시뮬레이터에서 XR Blocks 0.21.1 로드 성공.
- 숫자 1·2·3으로 광석을 선택하면 작은 섬이 생성되고 설명이 갱신됨.
- 실제 개인 기록이 아닌 더미 데이터만 사용.
- 코드는 `MineD_XRBlocks_v1/`에 있으며, Chrome에서 실행 가능한 최소 수직 슬라이스다.

### 아직 증명하지 않은 것

- Android XR 실제 기기의 손 추적과 공간 정합.
- 장시간 사용 시 편안함과 프레임 성능.
- 생성 영상 자동 다운로드·트랜스코딩·XR 자산 등록의 완전 자동화.
- 개인화 모델의 실제 배포 비용과 동시 사용자 성능.

## 수업 내용과의 인과성

1. 서로 다른 기록을 비교 가능한 특징으로 표현한다.
2. 특징을 4축·방향·검증 등급으로 구조화해 광석으로 만든다.
3. 챗봇이 근거 검색과 질문을 통해 사용자의 의도를 구조화한다.
4. 구조화된 설계도를 생성 모델의 입력으로 사용한다.
5. 사람의 검수와 명시적 승인으로 결과를 선택한다.
6. XR Blocks가 승인된 결과를 상호작용 가능한 개인 월드로 실행한다.

즉, 수업에서 다룬 `데이터 표현 → 모델 입력 → 생성 → 검증`이 Mine D에서는 `기록 → 광석 → 민디 대화 → 섬 설계도 → 영상 → XR 섬`으로 구현된다.
