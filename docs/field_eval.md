# 실제 기록 평가 절차

합성 인물 평가(`docs/eval.md`)는 정답을 우리가 만들었기 때문에 판정이 실제 삶에서도 맞는지는 알려 주지 않습니다. 이 절차는 팀원 4명(또는 동의한 지인)이 자기 기록으로 판정을 확인하고, **숫자만 담은 보고서**를 멘토에게 넘기는 방법을 정합니다. 기록 원문과 날짜는 기록 주인의 기기 밖으로 나가지 않습니다.

## 참가자가 하는 일

화면에서 하는 방법(권장)과 명령줄에서 하는 방법이 있습니다. 판정 코어는 두 방법 모두 같은 파이썬 코드(`core/mined_core/field_eval.py`)를 씁니다.

### 화면에서

1. 앱을 열고 **기록을 가져오기 전에** 가져오기 화면 아래의 "사건 먼저 적기"를 누릅니다.
2. 날짜가 확실한 일을 5~15개 적습니다. 종류는 세 가지입니다.
   - 힘들었던 일: 아팠던 주, 시험·마감, 이별처럼 며칠에서 몇 주 이어진 일
   - 좋았거나 특별했던 일: 여행, 행사, 큰 발표
   - 계속되는 변화: 이사, 이직, 입학, 기기 교체처럼 그 뒤로 생활이 달라진 일(시작한 날만)
3. "봉인하기"를 누릅니다. 봉인하면 사건 목록의 SHA-256 값이 저장되고 목록을 고칠 수 없습니다. 봉인을 풀면 푼 횟수가 보고서에 남습니다.
4. 기록을 가져와 판정합니다.
5. 머리의 "평가" → "가린 주 고르기"에서, 판정된 주와 평범한 주를 같은 수만큼(최대 10주씩) 섞은 목록에 하나씩 답합니다. 어느 쪽인지는 화면에 나오지 않습니다. 이 단계에서는 지층 화면을 보지 않습니다.
6. 참가 코드(멘토가 알려 준 P1~P4 같은 코드)를 적고 "계산하기"를 누릅니다. 15년 기록은 1~2분 걸립니다.
7. 화면에 뜬 표와 원문(JSON)을 직접 확인한 뒤 "보고서 내려받기"를 눌러 `mined_eval_<코드>.json` 을 멘토에게 보냅니다.

### 명령줄에서

```bash
cd web && npm run assets        # 처음 한 번(Pyodide 런타임)
npm run cli -- ~/내보내기/ -o ~/mined-out --events 사건.json --participant P1
```

`사건.json` 은 `[{"start": "2025-03-03", "end": "2025-03-21", "kind": "hard"}]` 모양입니다. 명령줄에는 봉인과 가린 평가 단계가 없으므로 보고서에 `"via": "cli"`, `"seal": {"sealed": false}` 로 적힙니다. 결과를 보기 전에 사건 파일을 먼저 만들어 두는 순서는 참가자가 지켜야 합니다.

## 보고서에 들어가는 것과 빠지는 것

- 들어가는 것: 판정 설정, 기간(주 수·년), 채널별 관측 주 수와 출처 앱 이름, 판정 수, 아래 평가 숫자, 봉인 해시와 봉인 횟수, 가린 평가의 답 개수.
- 빠지는 것: 날짜(YYYY-MM-DD, YYYY-Www 모양), 사건 메모, 메모·메시지·사진 원문, 이름.
- 날짜처럼 보이는 값이 하나라도 섞이면 파이썬 쪽과 화면 쪽 모두 보고서를 만들지 않습니다(`find_dates`, `findDates`).

## 보고서 숫자 읽는 법

| 항목 | 뜻 | 합성 기준값(long / elder / short) |
|---|---|---|
| `result.candidate_rate` | 판정할 수 있었던 주 가운데 판정된 주의 비율 | 11% / 8% / 12% |
| `chance_rate_far` | 적은 사건에서 먼 주(앞뒤 3주 밖)가 판정된 비율. 낮을수록 우연 판정이 적다 | 8% / 5% / 0% |
| `anchors.event_recall_pm1` | 적은 일 가운데 앞뒤 1주 안에 판정된 주가 있는 비율 | 79% / 90% / 67% |
| `anchors.enrichment`, `p_value` | 사건 앞뒤에 판정이 우연보다 몇 배 몰렸는지(판정 순서를 원형으로 돌린 귀무모형) | 1.73배 / 3.43배 / 2.81배 |
| `persistent_boundaries.recall` | 계속되는 변화 앞뒤 6주 안에 시기 경계가 있는 비율 | 50% / 100% / 100% |
| `ratings` | 가린 주에 "기억에 남는다"고 답한 비율(판정된 주 대 평범한 주)과 피셔 정확 검정(한쪽) p | 합성 인물에는 없음 |
| `holdout.<채널>.lift` | 그 채널을 빼고 판정한 주에서, 뺀 채널도 평소 범위를 벗어난 비율 ÷ 무작위 주 비율 | 가장 높은 채널 sns 1.46 / photo 1.95 / photo 2.10 |
| `window` | 창을 26주·104주로 바꿨을 때 판정 주의 자카드 계수 | 0.49·0.63 / 0.44·0.66 / 0.32·0.90 |
| `missing.kept_both` | 결측 구간을 0 또는 평소 값으로 채워도 남는 판정의 비율 | 97% / 100% / 100% |
| `configs` | 추세 보정 끔, 배지 기준 5%, 배지 하나 극단도 판정일 때의 같은 숫자 | 전체 계산에서만 |

기준값은 `core/scripts/field_collect.py --with-synth` 로 다시 만들 수 있습니다.

## 모으기

```bash
core/.venv/bin/python core/scripts/field_collect.py 받은보고서/*.json --with-synth -o out/field_eval_table.md
```

참가자별 한 줄과 합성 기준값 세 줄이 한 표로 나옵니다. 보고서에는 숫자만 있으므로 이 표는 팀과 멘토가 함께 봐도 됩니다.

## 해석할 때 주의할 점

- 참가자가 4명이면 사람 사이 차이를 일반화할 수 없습니다. 사람마다 "사건 재현율·집중도가 합성 기준값과 같은 범위인가"만 봅니다.
- 사건은 참가자가 기억하는 일만 들어가므로, 조용히 지나간 변화(판정은 맞았지만 기억에 없는 주)는 우연 판정으로 셉니다. 그래서 `chance_rate_far` 는 실제 오판정률의 상한에 가깝습니다. 가린 평가가 이 빈틈을 조금 메웁니다.
- 봉인 전에 지층 화면을 봤다면(`seal.before_result` 가 false) 사건 목록이 결과에 끌려갔을 수 있으므로 표에서 따로 표시합니다.
- 기록이 2년보다 짧으면 창 52주 기준이 1년 치밖에 없어 판정할 수 있는 주가 적습니다. `span.judged_weeks` 를 함께 봅니다.
