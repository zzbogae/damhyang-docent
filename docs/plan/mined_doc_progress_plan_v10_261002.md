## 1. 「같은 데이터면 같은 광물」 — 기준 (axes.py `pick_gem` 기준)

「같은 데이터」는 **같은 내용(무슨 말을 했는지)이 아니라 같은 숫자**입니다.

1. 그 주의 4축 값: 걸음(move) · 쉼(rest) · 화면(watch) · 기록(leave)
2. 각 축을 **그 사람의 직전 52주** 중위값·MAD 대비 robust z로 바꿈 (MAD=0이면 평균절대편차×1.2533)
3. 방향별 임계값 τ(TAU_UP / TAU_DOWN)를 넘은 축만 남김 — 없으면 「평범한 주, 광물 없음」
4. 가장 크게 벗어난 축 + 방향(많음/적음)으로 8종 결정
   - 걸음↑ 호박 / 걸음↓ pyrite(황철석) / 쉼↑ 청금석 / 쉼↓ 월장석 / 화면↑ 자수정 / 화면↓ rose / 기록↑ 흑요석 / 기록↓ 석류석
5. 다른 축도 함께 벗어났고, 그 축들을 채운 **데이터 출처 계열이 2종 이상**이면 → 형석(교차검증된 주)
6. 난수 없음 → 같은 4축 값 + 같은 직전 52주 이력이면 언제나 같은 광물

※ 카톡·메모의 **내용**은 광물 결정에 들어가지 않습니다. 내용은 섬(대화·단어 선택)에서만 쓰입니다.

## 2. 섬 생성 로직 — 다이빙 시나리오 (보경님 원안을 원칙 안에서 구현하는 버전)

보경님 원안에서 「AI가 결론을 내린다」(연말에 다이빙 가고 싶구나) 부분만 **「민디는 사실을 펼치고, 결론은 사용자가 말한다」**로 바꾸면 원칙 1(관측소 무판단)과 09-26 공간생성 v2 확정(앱이 스스로 원하는 공간을 정하지 않음)을 지키면서 같은 경험을 만들 수 있습니다.

```
민디   요즘 대화에 이런 말들이 있었습니다.
       [바다] [자전거] [칵테일] [다이빙] [수영장]
사용자 (바다를 고름)
민디   바다 하면 어떤 장면이 떠오르세요?
사용자 바닷속을 천천히 유영하면서 고래상어랑 복어랑 같이 있는 거.
민디   기록에는 이런 게 있었습니다.
       오래 머문 여행지 세 곳이 모두 다이빙 포인트였습니다.
       「다이빙」이라는 말이 올해 대화에 스물세 번 나왔습니다.
       캘린더에 수영장 일정이 매주 있습니다.
사용자 맞아, 연말엔 꼭 가고 싶은데 지금은 너무 바빠.
민디   그 바다를 섬으로 열어볼까요?
       → 생성: 해변 → 입수 → 수중 유영(고래상어·환도상어·복어) 1인칭
민디   이 섬의 이름을 붙여주세요.
사용자 연말의 바다
```

- 사실(사진·카톡·유튜브·캘린더 집계)은 **기기 안에서** 계산, 생성 도구로는 **사용자가 말한 장면 + 고른 단어만** 보냄
- 결론(「가고 싶다」)은 사용자의 입에서 나옴 → 판정 아님
- 숫자는 예시(가짜). 실제 값은 freq_scan·채널 집계에서
