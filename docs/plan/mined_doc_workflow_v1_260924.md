## 0. 왜 지금 바꾸는가

9/12 멘토 구현본이 들어오면서 **일의 성격이 바뀌었습니다.**

```
9월까지   만드는 국면 — 파서·판정·앱을 우리가 짬
10월부터  합치는 국면 — 멘토 뒷단 + 우리 규칙 + 하빈 디자인 시스템
```

만드는 국면에서는 창을 많이 열어두는 게 맞았습니다. **합치는 국면에서는 반대입니다.**
지금 문제는 창이 길어진 게 아니라 **상태가 네 군데(창 3 + 레포)에 흩어져 있는 것**이고, 09-18 인계서가 지적한 「창 간 지연」이 그대로 남아 있습니다.

## 1. 창 구조 — 셋에서 둘로

### 지금

| 창 | 범위 |
|---|---|
| A — 팀·파일 | 회의 · 팀원 · 드라이브 · 대외 컨택 |
| B — 경험설계 | 세계관 · 민디 · 대사 · 화면 문구 · 발표 문장 |
| 데이터·코드 | 파이프라인 · 판정 로직 · 앱 구현 |

### 10월부터

| 창 | 범위 | 열어두는 방식 |
|---|---|---|
| **데이터·코드** | 파이프라인 · 판정 · **멘토 코드 병합** | **상시** |
| **경험설계(B)** | 세계관 · 민디 · 대사 · 화면 문구 · 발표 | **상시** |
| 팀·파일(C) | 회의 · 드라이브 · 대외 | **필요할 때만** — 주 1회 시트 정리, 회의 전, 대외 컨택 |

**C를 상시에서 뺍니다.** 회의·파일 정리는 주기적인 일이라 항상 열어둘 필요가 없고, 지금 병목이 전부 창 B에 몰려 있습니다 — L1(숫자를 사람 말로) · `broken` 문안 · 편지 5시점 승인 · 민디 LLM L1~L8.

**⚠ 창 B가 밀리면 11월이 무너집니다.** 데이터 창이 아무리 빨라도 화면에 나갈 문장이 없으면 못 씁니다.

### 창 경계가 흐려질 때

합치는 국면에서는 「멘토 코드의 이 문장을 우리 문구로 바꾸기」처럼 **두 창에 걸친 일**이 늘어납니다.

> **규칙** — **사실 판단은 데이터 창, 문장 판단은 창 B.**
> 「v7이 이 경우를 어떻게 처리하는가」는 데이터 창.
> 「그걸 화면에 뭐라고 쓸 것인가」는 창 B.
> 애매하면 데이터 창에서 사실을 확정한 뒤 창 B로 넘깁니다. 반대로 하면 문장을 먼저 정하고 사실을 맞추게 됩니다.
