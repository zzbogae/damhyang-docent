## 1. 축 — 이름이 두 층입니다

```python
'move':  {'label': '움직임', 'screen': '걸음'}
'rest':  {'label': '쉼',     'screen': '쉼'}
'watch': {'label': '보기',   'screen': '화면'}
'leave': {'label': '남기기', 'screen': '기록'}
```

`label` 은 문서·로그·회의용 내부 약칭. `screen` 이 화면에 나갑니다.
앱은 `axis_screen(ax)` 로 읽습니다.

**`rest` 를 「잠」이 아니라 「쉼」으로 둔 이유** — 수면 커버리지가 19%뿐이라
밤 무기록 구간 대체 지표가 들어올 예정입니다. 「잠」이면 그때 이름이
내용보다 좁아집니다. (창 B 확정 · 화면문구_규칙_v3 §4)

## 2. 방향별 τ

| 축 | τ 위 | τ 아래 | v2 공통 |
|---|---|---|---|
| move | 4.91 | 1.60 | 3.03 |
| rest | 2.21 | 2.99 | 2.36 |
| watch | 2.48 | 1.44 | 1.99 |
| leave | 2.85 | 1.37 | 2.16 |

**왜** — 건수형 지표는 오른쪽 꼬리가 깁니다. 아래로는 0이라는 바닥이
있어 갈 데가 없습니다. `|z|` 하나로 자르면 그 문턱을 위쪽이 거의 다
먹습니다.

**실측 (800주)** — 아래 광물 4주 → **33주**, 안 쓰인 광물 2종 → **0종**,
전체 광물 수는 그대로(129주 = 16%).

「덜 움직인 주」가 우리 세계관의 핵심인데 공통 τ 3.03 으로는 영원히
안 잡혔습니다.

## 3. 결 — 광물과 분리

광물은 τ(얼마나 드문가), 결은 z 크기(얼마나 벗어났나)로 정합니다.

| 결 | 뜻 | 주 수 |
|---|---|---|
| `mixed` | 2축 이상 밴드 밖 | 136 (17%) |
| `coarse` | 1축만 밴드 밖 | 299 (37%) |
| `regular` | 전부 밴드 안 | 365 (46%) |

**광물은 없는데 결이 평평하지 않은 주가 309주.** 묶어놓았을 때는
이 309주가 전부 같은 무늬였습니다.

## 4. 확인 등급 4종 — 정본은 `GRADE_TEXT`

| 등급 | 조건 | 화면 |
|---|---|---|
| `held` | 4주 내 복귀 + 4주 지속 | 그 뒤 4주는 평소 범위였습니다 |
| `returned` | 4주 내 복귀, 그 뒤 미확인 | 돌아왔지만 그 뒤는 확인되지 않았습니다 |
| `open` | 창이 아직 안 닫힘 | 이 주 뒤는 아직 확인되지 않았습니다 |
| `insufficient` | 기록이 비어 판정 불가 | 기록이 비어 판정할 수 없습니다 |

### 변수명 개명 (2026.09.19 · 보경 승인)

코드가 쓰는 이름을 판정 결과와 같은 말로 맞췄습니다.

```
recovered → held      passed → returned      observed → open
```

**옛 이름도 계속 읽습니다.** 이미 만들어진 `gyeol_data.json` 이 전부
옛 이름을 들고 있어서, 버리면 그 파일이 화면에서 빕니다.

| 어디 | 어떻게 |
|---|---|
| 파이썬 | 새 이름만 씁니다. 매번 `data/` 에서 새로 만들어서 옛 값을 읽을 일이 없습니다 |
| 앱 | `TIER_N()` 한 줄이 옛 이름을 새 이름으로 바꿔 읽습니다 |
| `axes.py` | `TIER_ALIAS` · `normalize_grade()` 가 정본 |

`grade_text()` 는 옛 이름을 넣어도 맞는 문장을 돌려줍니다.

`insufficient` 는 앱에 자리가 없습니다. **열린 항목.**

세는 자리 명사구 (문장을 못 넣는 곳):
- `held` → **그 뒤 4주가 평소 범위였던 주**
- `returned` → **평소 범위로 돌아왔지만 그 뒤는 확인 안 된 주**
- 카운트 문형 → **살펴본 N주 중 M주** (「전체 판정 N건」 교체)

## 5. 결측 맥락 줄 (§7-③)

```
그 뒤 4주는 평소 범위였습니다
그 주에 평소 있던 기록 중 1종이 비어 있습니다      ← 조건부
```

**왜** — 첫 줄만 있으면 기록이 멈춘 주가 「아무 일도 없던 주」로 읽힙니다.
실제로는 잴 것이 없었던 주입니다. 둘째 줄은 첫 줄을 판정하지 않으면서
첫 줄만으로는 안 보이던 것을 보이게 합니다.

**「평소 있던」의 기준** — 직전 52주 중 **절반 이상** 나타난 계열.
더 낮추면 옛날에 한두 번 쓴 앱이 영원히 「평소 있던 것」으로 남아
매주 결측으로 잡힙니다. **그 주 이전만 봅니다** — 미래를 보면 안 됩니다.

빈 계열이 0이면 `context_lines` 가 빈 배열이라 **줄 자체가 안 나옵니다.**

## 6. 사유 문장 — 정본 한 곳 (v3 신규)

```python
REASON = {
    'one_family': '이 시기엔 {only} 기록만 남아 있습니다 — '
                  '한 지표만으로는 그 뒤가 어땠는지 말하지 않습니다',
    'not_held':   '그 뒤가 평소 범위였는지는 아직 확인되지 않았습니다',
}
```

`judge.py` · `analyzer_v3.py` · `rolling_baseline.py` 가 「근거가 얇다」는
**같은 상황에 각자 다른 문장을 들고 있었습니다.** 어느 모듈이 도는지에
따라 화면이 달라지는데, 그건 사용자가 고를 수 있는 게 아닙니다.
셋 다 `reason_text()` 를 부르게 바꿨습니다.

**⚠ 다른 파일에 사유 문장을 직접 쓰지 마세요.** 쓰는 순간 두 벌이 됩니다.

### 「비노출」 철회

v2 논의에서 `analyzer_v3` · `rolling_baseline` 의 `reason` 을 화면에서
숨기기로 했다가 **철회했습니다.**

- 옛 문장이 문제였던 건 「회복」 때문만이 아니라 **개조식이었고**
  앱이 자기 판정 과정을 설명하는 메타 문장이었기 때문입니다
- 바꾼 문장은 사실 진술입니다. 나가도 됩니다
- 사용자가 연 주에 대해 앱이 아는 것을 숨길 근거가 없습니다 (원칙 6)

진짜 문제는 노출 여부가 아니라 **문장이 두 벌인 것**이었습니다.
