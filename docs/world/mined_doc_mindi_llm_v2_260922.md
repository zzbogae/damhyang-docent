## 1. 숫자를 사람 말로 — 해결 방향

### 문제

「평소 범위」·「4주」·「하위 3%」는 통계 용어입니다. 사람 말이 아닙니다.
두 안 모두 반려 이유: 「평소」라는 개념이 여전히 통계입니다.

### 해결 원칙

> **통계 용어를 설명하는 게 아니라, 통계가 가리키는 실제 기록을 꺼냅니다.**

집계 사실과 기준 설명을 한 문장에 담지 않습니다. 분리합니다.

### 확정 문안

| 자리 | 문장 |
|---|---|
| 집계 | 그런 주가 15년 중 여섯 번 있었습니다 |
| 계단 3 열기 | 그중 다섯 번은, 그다음 달에 이런 기록이 남아 있습니다 |
| 카드 | *(판정 문장 또는 원문 — 민디가 짓지 않음)* |

- 「15년 중」은 보경 이력 기간. **변수로 받아 찍습니다**
- 「평소 범위였습니다」 삭제. 대신 **그다음 달의 기록이 무엇인지를 카드가 보여줍니다**
- 사용자가 직접 읽으면서 결론을 냅니다. 앱이 결론을 말하지 않습니다

## 2. 「나머지 한 번은 그렇지 않았습니다」 — 고정 문안

### 확정

> **나머지 한 번은 그렇지 않았습니다.**

### 조건

- 여섯 번 중 다섯 번일 때만 나옵니다
- 전부 같은 방향이면 이 줄은 안 나옵니다
- 숫자가 달라지면 문장도 달라집니다 (변수)

### 이유

다섯을 말하고 하나를 안 말하면 「대부분 괜찮아지더라」는 위로가 됩니다.
품질기준 4(거짓 해소 금지) · 발표 ⑩의 「마무리를 지어주지 않는다」와 같은 자리입니다.

## 3. LLM 하드룰 수정 — 온디바이스면 원문 허용

### 확정

| 방식 | 허용 |
|---|---|
| 원문 → API → 서버 | ❌ 기존 금지 유지 |
| 원문 → 기기 안 모델 | ✅ 온디바이스에 한해 허용 |

### 이유

규칙의 목적은 「원문이 기기를 떠나지 않는 것」이었습니다.
온디바이스 모델은 그 목적을 지키면서 원문을 읽을 수 있는 유일한 방법입니다.
규칙의 정신을 뒤집는 것이 아니라, 정신을 지키기 위해 조항을 수정합니다.

### 반영할 곳

세계관설계서·절대원칙에 이 구분을 명시합니다.
지금 「원문을 AI에 넘기지 않는다」는 조항이 온디바이스까지 막는 것으로 읽힐 수 있습니다.

## 4. 사용자 이름 붙이기 — 도입 확정

### 흐름

```
민디   이 주에 이름을 붙이시겠어요?

       그 주에 이런 말들을 쓰셨습니다
       ┌────────────────────────────
       │  마감   새벽   못 자겠다   끝나면
       └────────────────────────────
       그대로 쓰셔도 되고, 다르게 쓰셔도 됩니다.

보경   마감 지옥

       ─── 몇 달 뒤 ───

민디   이번 주가 「마감 지옥」이라고 부르셨던 주와 닮았습니다.
```

### 원칙 점검

| | |
|---|---|
| 원칙 1 판정 안 함 | 사용자가 붙인 이름입니다 |
| 원칙 4 새 데이터 수집 안 함 | 편지와 같은 논리 — 두고 가는 것 |
| 원칙 7 「더 나은」은 앱이 안 말함 | 「자기 편지에 쓰는 건 자유」와 같은 자리 |

### 후보 출처 규칙

| 순위 | 출처 | 비고 |
|---|---|---|
| 1 | 그 주 본인 어휘 — 명사·명사구 빈도 (형태소 분석기) | 기본 |
| 2 | 전에 붙인 이름 | 쌓이면 |
| 3 | 사실 조각 (「새벽에 쓴 주」·「사진이 없던 주」) | 메모가 없을 때 |
| ❌ | 앱이 만든 감정 단어 목록 | 절대 안 됩니다 |

### 추가 조건

- 이름은 그 주의 코어에 붙는 태그. **로컬에만 남습니다**
- **이름을 지울 수 있어야 합니다.** 붙이는 것이 자유면 지우는 것도 자유입니다

## 5. 인용 ≠ 해석 — 선 확정

**모델이 원문을 바꿔 말하는 순간 해석이 시작됩니다. 이 문장을 모델 평가 기준의 첫 줄로 씁니다.**

| | |
|---|---|
| "11월 27일에 이렇게 쓰셨습니다 — [원문 그대로]" | ✅ 인용 |
| "그때 많이 지쳐 계셨네요" | ❌ 판정 |
| "메모 다섯 개가 다 밤 두 시 넘어서였습니다" | ✅ 사실 |
| "밤에 못 주무신 것 같아요" | ❌ 추측 |
| "이런 모양의 주가 여섯 번 있었습니다" | ✅ 집계 |
| "자주 이러시는 편이네요" | ❌ 평가 |
| "이 주에 메모가 5개였습니다" | ✅ 집계 |
| "많이 쓰셨네요" | ❌ 평가 (「많이」가 평가입니다) |

## 6. 되묻기 조건 — 확정

- **사용자가 먼저 대화를 연 뒤에만**
- **한 번의 대화에서 한 번.** 연속으로 물으면 인터뷰가 됩니다
- 앱이 불쑥 물으면 원칙 3(먼저 말 걸지 않는다) 위반

---

## 7. 이름 후보 안내 문구 — 확정

> **그대로 쓰셔도 되고, 다르게 쓰셔도 됩니다.**

경어 완충재(「원하시면」·「괜찮으시면」)를 더 붙이면 민디 문체가 무너집니다. 이대로 씁니다.

## 8. 대화 유형별 응답 틀 — 확정

| 사용자가 | 민디가 |
|---|---|
| "이 광물 뭐야?" | 축 + 방향 + 언제 + 「그 주로」 버튼 |
| "이런 주가 또 있었어?" | 닮은 주 3개 카드 (이미 계산돼 있음) |
| "형석은 왜 형석이야?" | 계열 2종 이상이 같은 주를 가리켰다 |
| "그때 왜 그랬어?" | 모른다 말한 뒤 **그 주 기록 카드** |
| "제일 힘들었던 때는?" | **거절 + 광물 카드 3개** |

### 거절 문안 — 「제일 힘들었던 때는?」

> **제일이 어딘지는 말하지 않겠습니다. 대신 이런 주들이 있었습니다.**
> *(광물 카드 3개)*

「모릅니다」로 끝내지 않습니다. 거절 직후 기록을 꺼냅니다 (부록 D 원칙).

### 「그때 왜 그랬어?」

> **그때 이런 기록이 있었습니다.**
> *(그 주 메모 원문 카드)*

이유를 말하지 않습니다. 기록을 꺼내고, 이유는 사용자가 읽으면서 냅니다.
