# 편지 구조 개정안
2026.09.07 | 창 C → 창 B | 창 B 8/31 확정안의 개정 제안

> 두 가지가 바뀝니다. **대화 전체를 남깁니다**, 그리고 **알림을 켭니다.**
> 둘 다 제가 앞서 반대했던 것인데, 다시 보니 반대 근거가 약했습니다. 아래에 이유를 적었습니다.

---

## 1. 대화 맥락 — 제가 틀렸습니다

### 1-1. 제가 했던 말과 그 문제

> "민디의 말은 편지에 안 들어갑니다. 내가 한 말만 저장합니다."

**그러면 읽을 수가 없습니다.** 1년 뒤에 열었을 때 이런 게 나옵니다.

```
"응, 그때도 그랬네."
"그건 좀 다른 것 같아요."
```

무슨 얘기였는지 모릅니다. **맥락 없는 내 말은 남의 말보다 못합니다.**

### 1-2. 제가 걱정했던 것 — 다시 보니 기우입니다

걱정: *민디 대사가 미래로 배달되면, 앱이 미래의 나에게 말을 거는 게 된다.*

그런데 **시제가 다릅니다.**

| | |
|---|---|
| 앱이 미래에 말을 건다 | 미래 시점에 앱이 **새로 생성한** 문장을 보내는 것 |
| 그날의 대화가 남는다 | **그때 있었던 일**을 그대로 보여주는 것 |

**후자는 우리가 이미 하고 있는 일입니다.** 원문 카드가 정확히 그겁니다 — 2024년에 쓴 메모를 지금 그대로 꺼내는 것. 민디의 그날 대사도 같은 성격입니다.

그리고 민디 대사는 **판정을 담고 있지 않습니다.** 사실과 위치만 말합니다. 1년 뒤에 읽어도 판정이 되지 않습니다. 애초에 위험이 없었습니다.

### 1-3. 그래서 이렇게 나눕니다 — 편지 / 대화 기록

```
┌─────────────────────────────────────┐
│  편  지                              │  ← 미래로 배달되는 것
│                                      │     내가 쓴 것
│  2026년 9월 6일                      │
│  · 이 주는 새벽에 남긴 글이           │  ← 앱이 인쇄한 사실 한 줄
│    평소보다 많았습니다.               │
│                                      │
│  (내가 쓴 본문)                       │
│                                      │
├─────────────────────────────────────┤
│  ▸ 그날의 대화 보기                   │  ← 접혀 있음. 펴면 전문
└─────────────────────────────────────┘
```

| | 무엇 | 주인 |
|---|---|---|
| **편지 본문** | 내가 쓴 것. 미래의 나에게 | **나** |
| **그날의 대화** | 민디와 주고받은 전문. 맥락 | 그날의 기록 |

**편지는 배달물이고, 대화는 첨부물입니다.** 편지의 주인은 여전히 나입니다.

### 1-4. 그러면 편지 쓰기가 훨씬 쉬워집니다

지금 설계는 **백지에 쓰게** 합니다. 그게 제일 어렵습니다.
대화를 하고 나면 이미 할 말이 만들어져 있습니다. **민디가 마지막에 이렇게 물으면 됩니다.**

> **"지금 하신 말, 남겨둘까요?"**
> "언제 받아보시겠어요?"

마음을 묻지 않고 **처리를 묻습니다.** 이건 허용됩니다.

## 2. 알림 — 이것도 제가 좁게 봤습니다

### 2-1. 원칙의 원래 범위

「먼저 말 걸지 않는다」가 나온 자리는 **구글 포토 사례**였습니다.

> 내 의지와 상관없이 9년 전 기록이 툭 튀어나온다. 그걸로 소송까지 갔다.

즉 이 원칙이 막으려던 건 **원치 않는 과거가 앱의 판단으로 튀어나오는 것**입니다.
**편지는 그게 아닙니다.**

| | 편지 알림 | 우리가 막으려던 것 |
|---|---|---|
| 누가 시점을 정했나 | **사용자** | 앱 |
| 누가 내용을 썼나 | **사용자** | 앱 |
| 무엇이 오나 | 내가 나에게 보낸 것 | 앱이 고른 과거 |

**알람 시계가 울리는 건 「먼저 말 걸기」가 아닙니다. 내가 맞춰놓은 겁니다.**

### 2-2. 그래서 선을 이렇게 다시 긋습니다

| 허용 | 금지 |
|---|---|
| ✅ 사용자가 예약한 편지 도착 | ❌ 앱이 고른 과거 주 알림 |
| ✅ 사용자가 정한 시점 | ❌ 앱이 정한 시점 |
| ✅ 사용자가 쓴 내용 | ❌ 앱이 만든 문구 |

**셀프리치와의 차이가 여기서 더 선명해집니다.**
> 셀프리치는 **앱이 매일 질문을 보냅니다.**
> Mine D는 **내가 나에게 보낸 것만 도착합니다.**

같은 알림이지만 발신자가 다릅니다. 발표에서 대조로 쓸 수 있습니다.

### 2-3. ⚠ 세계관설계서 문구를 정밀화해야 합니다

지금 원칙이 통째로 금지라 이 구분이 안 담깁니다.

| 현재 | 바꿀 것 |
|---|---|
| 「먼저 말 걸지 않습니다」 | 「**앱이 고른 것으로** 먼저 말 걸지 않습니다.<br>**당신이 맡긴 것은 약속한 날에 돌려드립니다.**」 |

**앞 문장만 있으면 금지고, 뒤 문장이 붙으면 약속이 됩니다.**

## 3. 시점 — 5개로 (하루가 들어옵니다)

| | 시점 | 알림 | 왜 |
|---|---|---|---|
| ① | **하루 뒤** | ✅ | **신설.** 「내일의 내가 조금 달라진다」의 실행 장치 |
| ② | 일주일 뒤 | ✅ | |
| ③ | 한 달 뒤 | ✅ | |
| ④ | 1년 뒤 | ✅ | |
| ⑤ | 3년 뒤 | ❌ | **빈 받침대.** 알림 없이 자리만 |

### 「하루 뒤」가 제일 중요합니다

목적 문장이 *"그 느낌이 내일 하루를 아주 조금 다르게 만듭니다"*인데,
**지금까지 그걸 실제로 만드는 장치가 없었습니다.** 다음 주는 너무 멉니다.

```
오늘  과거를 본다 → 대화한다 → 내일의 나에게 한 줄 남긴다
내일  그게 도착한다
```

**목적 문장이 기능으로 구현됩니다.** 그리고 재방문 주기가 하루가 됩니다 — 지금 설계에서 가장 짧은 주기가 일주일이라 재방문 동력이 약했습니다.

### 리듬이 규칙적입니다

`1일 → 7일 → 30일 → 365일` — 대략 7배씩 늘어납니다.
**의도적으로 정한 게 아니라 자연스러운 간격인데, 그래서 외우기 쉽습니다.**

### 3년만 알림이 없는 이유

3년 뒤에 이 앱이 있을지 모릅니다. 알림을 약속하면 **못 지킬 약속**이 됩니다.
받침대만 두면 약속이 아니라 **자리**가 됩니다. 「의도된 미완결」이 그대로 살아 있습니다.

> 민디 — "3년 뒤 자리는 아직 비어 있습니다. 받침대만 놓아두겠습니다."

## 4. D-day 문제가 저절로 풀립니다

앞서 「남은 날짜를 표시하지 않는다 — 카운트다운은 스트릭이다」로 정했습니다.

**알림이 있으면 D-day가 필요 없습니다.** 평소엔 안 보이다가 그날 도착합니다.
오히려 **알림이 카운트다운을 대체합니다.** 세는 건 앱이 하고, 사용자는 세지 않습니다.

| | |
|---|---|
| 편지함 | 열릴 날짜 **표시 안 함** |
| 도착일 | 알림 한 번 · 관측소에 봉인 풀린 코어가 빛남 |
| 놓쳤을 때 | 사라지지 않음. 다음에 와도 있음 |

**마지막 줄이 「지키지 않아도 괜찮아」입니다.** 놓쳐도 없어지지 않습니다.
