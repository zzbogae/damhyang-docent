## 1. 레퍼런스 영상에서 본 것

끝없이 펼쳐진 초록 습지·들판 위로 압도적인 높이의 낡은 탑형 건물이 솟아 있고, 그 복도·발코니를 1인칭으로 걷거나 걸터앉아 쉬는 장면이 반복됨. 녹슨 난간, 벗겨진 페인트, 화분, 빨래줄, 낡은 철문 같은 생활감 있는 디테일이 가득하고, 중간중간 **발·다리가 프레임에 보이는 채로** 욕조에 몸을 담그거나(고무오리) 노을 지는 테라스에 다리를 뻗고 쉬는 장면이 나옴. 조명은 맑은 대낮(파랑·하양)과 노을(핑크·퍼플·오렌지)이 교차.

## 2. 설계에 반영할 핵심 장치 5가지

1. **1인칭 신체 현존감** — 발·손이 프레임에 보이는 것 자체가 "내가 여기 있다"는 느낌을 만드는 핵심 장치. 배경만으론 부족함.
2. **압도적 스케일 + 광대한 수평선** — 섬이 끝없는 지평선 위에 홀로 선 구조물로 보이면 "나만의 섬" 컨셉과 시각적으로 맞음.
3. **낡고 다정한 디테일(worn & lived-in)** — 완벽하지 않고 녹슬고 벗겨졌지만 화분·빨래가 있는 디테일. 광물(기억)이 쌓여 생긴 "흔적"과 자연스럽게 연결.
4. **조명 톤 양극단** — 맑은 대낮(파랑·하양) ↔ 노을(핑크·퍼플·오렌지). 색온도 파라미터의 실제 양 끝값.
5. **작은 개인 오브제** — 고무오리·촛불·유리잔. 공간을 "나만의 것"으로 완성하는 디테일 소품.

## 3. 카테고리/파라미터 표 (갱신)

### ① 고정 카테고리 (이산 선택, 규칙표)
| 카테고리 | 값 예시 |
|---|---|
| 배경 유형 | 숲 · 바다 · 사막 · 습지평원 · 도시 |
| 시간대 | 새벽 · 낮 · 노을 · 밤 |
| 랜드마크 스케일 | 없음 · 중간 · 압도적(거대 구조물) |
| 전경 개인 오브제 | 음료잔 · 책 · 식물 · 인형 등 |
| 1인칭 신체 파츠 | 없음 · 발만 · 손만 · 발+손 |

### ② 연속 파라미터 (무드 기반, 기존 축·z-score 방식과 동일한 접근)
| 파라미터 | 양 끝값 |
|---|---|
| 색온도 | 따뜻함 ↔ 차가움 |
| 채도/대비 | 선명함 ↔ 바램 |
| 질감 마모도 | 깨끗함 ↔ 낡고 녹슨 |
| 생동감 | 고요함 ↔ 활기참 |
| 초현실감 | 현실적 ↔ 몽환적(드림코어) |

①은 freq_scan.py가 뽑은 단어를 결정론적 규칙표로 매핑, ②는 대화의 무드를 수치화해 연속값으로 적용 — 기존 "같은 데이터면 같은 광물"과 동일한 논리를 유지하면서도, 매번 똑같은 공간이 나오지 않도록 함.

## 4. 연구 질문 — "이런 영상을 LLM에 학습시켜 구현할 수 있는가?"

**결론: "학습(훈련)"은 비현실적이고 불필요함. "분석"은 이미 가능하고 지금 한 것이 바로 그 예시임.**

- **지금 한 것 = 분석(in-context)**: 멀티모달 모델(Claude/Gemini 등)에 영상 프레임을 직접 보여주고 "이 영상의 무드가 뭐냐"고 물어서 스타일 descriptor를 뽑아내는 것. 비용·시간이 거의 안 들고, 지금 당장 쓸 수 있음.
- **"학습(fine-tuning)"은 다른 이야기**: 이런 영상 데이터셋을 모아 모델을 새로 훈련시키는 건 대규모 데이터·GPU·시간이 필요한 별개의 작업. 2인 체제·이번 일정에서는 비현실적이고, 애초에 필요하지도 않음.
- **"저 영상과 똑같은 화면을 실제로 렌더링"하려면 LLM이 아니라 생성형 이미지/영상 모델(diffusion)이 필요함** — 이건 원칙 2(AI 생성 이미지) 논의를 다시 열게 됨. 사진→3D 변환 때와 같은 이유로, "사용자 데이터에 근거한 절차적 조합"이 아니라 "매번 새로 그려내는 이미지"가 되기 때문.
- **지금 단계에서 현실적인 경로**: 멀티모달 모델로 레퍼런스의 무드만 분석 → 그 descriptor를 위 ①·② 표의 파라미터로 변환 → XR Blocks가 기존 에셋·스카이박스·조명 프리셋을 조합해 "비슷한 느낌"을 절차적으로 재현. 완전히 같은 그림은 못 만들지만, 원칙과 충돌 없이 지금 가능한 선.
- 더 높은 시각적 완성도(저 영상과 거의 똑같은 룩)를 원한다면, 이건 라이브 생성이 아니라 **전시용 사전 제작 데모 영상**(이미 합의된 "3단계는 이미지로 대체" 방향)에서 외부 생성 도구를 쓰는 쪽으로 분리해서 접근하는 게 맞아 보임.

→ 이 질문, 수요일 이서연님 미팅 때 같이 물어보는 게 좋을 것 같습니다. "LLM으로 XR Blocks 연결 자동화 가능한지"와 사실상 같은 질문 계열이라 자연스럽게 이어집니다.
