1. **redesign §3 표는 쓸 수 없습니다.** 축 단위로 세는데 코드는 계열 단위로 세고, **예시가 자기 논리와 모순**입니다

## 1. 무엇을 고치는 과제인가

지금 화면에 나오는 교차검증 문구는 이렇습니다.

> "서로 다른 기록이 같은 시기를 가리켰습니다"

**왜 그게 신뢰의 근거인지를 말하지 않습니다.** redesign이 이 문제를 정확히 지적했고, 대안으로 §3 표를 냈습니다.

---

## 2. 그런데 §3 표에 모순이 있습니다

### 원문

| 함께 움직인 축 | 뒤에 붙이는 말 |
|---|---|
| 3축+ | **잠·걸음·기록 3축이 함께 내려갔습니다** → "기기 하나가 고장나도 셋이 같이 틀릴 수는 없습니다" |

### 문제

**잠과 걸음은 둘 다 애플헬스에서 옵니다.** 기기(또는 앱) 하나가 고장나면 **둘이 같이 틀립니다.**
즉 이 예시에서 뒤에 붙인 문장은 **성립하지 않습니다.**

같은 문서 §3 하단이 이걸 이미 알고 있습니다.

> "걸음·잠은 둘 다 헬스앱이라 — 기기 하나가 고장나면 둘이 같이 틀립니다 — 이 조합만으로는 교차검증이 아닙니다. (v5 로직)"

**표의 예시와 표 아래 조건이 서로 어긋납니다.** 축을 세면 3인데 출처를 세면 2입니다.

### 원인

**축과 계열은 다른 층위입니다.** 표는 축을 세고, 코드는 계열을 셉니다.

---

## 3. 축 4개 · 계열 6개

### 축 (게이지에 보이는 것)

| 축 | 계열 |
|---|---|
| 걸음 | 건강 |
| 잠 | 건강 |
| 화면 | 유튜브 |
| 기록 | 메모 · 사진 · 카톡 |

### 계열 (교차검증에 세는 것) — `channels.py` `FAMILY_LABEL`

| 계열 | 축 |
|---|---|
| 건강 기록 | 걸음 · 잠 |
| 유튜브 기록 | 화면 |
| 메모 기록 | 기록 |
| 사진 기록 | 기록 |
| 카톡 기록 | 기록 |
| **일정 기록** | **없음** |
| ~~AI 대화 기록~~ | 미반영 |

**여기서 두 가지가 드러납니다.**

- **걸음·잠 2축이 같이 움직여도 계열은 1개입니다.** 교차검증이 아닙니다
- **기록 1축 안에 계열이 3개 있습니다.** 메모와 사진이 같이 움직이면 **1축인데 교차검증입니다**

즉 **축 수로는 교차검증을 셀 수 없습니다.** 방향이 반대로 나오는 경우가 양쪽으로 있습니다.

> ⚠ **어제 문서 정정**: 「게이지 4축, 교차검증 5계열」이라고 썼는데 **5가 아니라 6입니다**
> (AI 대화 포함 7개 정의, 1개 미반영). 4축에 캘린더를 더해 5라고 센 것인데,
> 축과 계열이 1:1이 아니라 그 셈법이 성립하지 않습니다.

## 4. 확정 표 — 계열 수 기준

| 계열 수 | 표기 | 뒤에 붙이는 말 |
|---|---|---|
| **1개** | 건강 기록 하나만 움직였습니다 | 다른 기록은 평소 범위였습니다. **근거가 얇습니다** |
| **2개** | 건강·메모 2가지 기록이 같이 내려갔습니다 | **서로 다른 앱에서 온 기록입니다** |
| **3개 이상** | **건강·메모·사진 3가지 기록이 함께 내려갔습니다** | **앱 하나가 고장나도 셋이 같이 틀릴 수는 없습니다** |

### 살리는 것

**마지막 문장이 이 표의 존재 이유입니다.** "서로 다른 기록이 같은 시기를 가리켰습니다"가 의미불명이었던 건 **왜 그게 신뢰의 근거인지**를 말하지 않았기 때문입니다.

### 바꾸는 것

| | redesign §3 | 확정 |
|---|---|---|
| 세는 단위 | 축 | **계열** |
| 표현 | "3축이" | **"3가지 기록이"** |
| 마지막 문장 | "기기 하나가" | **"앱 하나가"** |

**「축」을 화면에 노출하지 않습니다.** 축은 게이지의 개념이고, 여기서는 사용자가 실제로 연결한 **앱 이름**으로 말하는 게 맞습니다. 「기기」보다 「앱」이 정확합니다 — 애플헬스와 삼성헬스는 기기가 달라도 같은 계열입니다.

## 5. 이미 있는 코드 문구는 유지합니다

`judge.py`가 계열 단위로 이미 두 단계를 처리하고 있습니다. **여기는 손대지 않습니다.**

| 조건 | 현재 문구 | 판단 |
|---|---|---|
| 지표 1개뿐 (`thin`) | "이 시기엔 [X] 기록만 남아 있습니다 — 한 지표만으로는 회복을 말하지 않습니다" | ✅ 유지 |
| 계열 1개 (`single_source`) | "다만 이건 [X] 한 종류만 보고 말한 것이라, 다른 기록이 더해지면 달라질 수 있습니다" | ✅ 유지 |

**둘 다 판정을 낮추는 쪽이고, 문장이 이미 정확합니다.**
§4 표는 **계열 2개 이상일 때 붙이는 말**로 추가되는 것이고, 기존 두 문구를 대체하지 않습니다.

```
계열 1개 → 기존 single_source 문구 (판정 낮춤)
계열 2개 → §4 "서로 다른 앱에서 온 기록입니다"
계열 3개+ → §4 "앱 하나가 고장나도 셋이 같이 틀릴 수는 없습니다"
```

## 6. 일정(캘린더)의 두 가지 용도

어제 문서에서 **「일정은 기준선이 없어 많고 적음을 말할 수 없다」고 썼는데 틀렸습니다.**
`judge.py`에 이미 있습니다.

```
'cal_events': '잡혀 있던 일정이 평소보다 적었습니다'
```

**일정도 이동기준선으로 판정받는 정식 지표입니다.** 계열이기도 하고요.

| 용도 | 문장 |
|---|---|
| **근거로 쓸 때** | "잡혀 있던 일정이 평소보다 적었습니다" — 기존 코드 그대로 |
| **맥락으로만 보여줄 때** | "그 주에 일정이 11건 있었습니다" |

**둘은 다른 자리입니다.** 근거는 판정에 쓰인 지표를 나열하는 자리고, 맥락은 판정과 무관하게 주 상세에 곁들이는 자리입니다. 후자에 많다·적다를 안 붙이는 건 **판정에 안 쓰였기 때문**이지, 기준선이 없기 때문이 아닙니다.

**축이 아니라는 결론은 그대로입니다** — 커버리지 19%, 그리고 하기로 한 일이라 성격이 다릅니다.

## 7. 고칠 곳

| 대상 | 무엇 | 누구 |
|---|---|---|
| `redesign_v1_260822.md` §3 | 표를 **계열 수 기준**으로 교체. 「잠·걸음·기록 3축」 예시 삭제 | 데이터 창 |
| `judge.py` | 계열 2개 이상일 때 §4 문구 추가. `thin`·`single_source`는 유지 | 데이터 창 |
| 주 상세 화면 | 교차검증 줄 표시 | 황하빈 |
| 소스 탭 | "2축만 채워져" → **계열 기준으로 다시 세야 함** (아래) | 황하빈 |
| 세계관설계서 | 「4축 / 6계열」로 정정 | 보경 |

### ⚠ 소스 탭도 같은 문제가 있습니다

redesign §7이 **"축 4개 중 지금 2개만 채워져 있습니다"**로 연결 동기를 만듭니다.
그런데 **애플헬스만 연결해도 축은 2개(걸음·잠)가 찹니다.** 계열은 1개인데 축이 절반 찬 것으로 보입니다.

> **"축 2개가 찼는데 교차검증되는 주가 없다"**는 상태가 나오고, 사용자는 이유를 모릅니다.

소스 탭은 **계열 기준으로 세야 합니다.**

> **지금 1가지 기록만 연결되어 있습니다.**
> 서로 다른 기록이 같은 주를 가리킬 때 비로소 확인이 됩니다.
> 메모나 사진을 더 넣으시면 두 번째 기록이 생깁니다.

**게이지는 축을 보여주고, 소스 탭은 계열을 셉니다.** 같은 숫자를 쓰면 안 됩니다.

## 8. 요약 — 축과 계열

> **축은 내가 어디에 있나를 보여주고, 계열은 그 말을 믿어도 되나를 셉니다.**
>
> 축 4개 · 계열 6개. **1:1이 아닙니다.**
> 걸음과 잠은 2축이지만 1계열이고, 기록은 1축이지만 3계열입니다.

이 한 문단이 오늘 하루 동안 세 번 틀린 지점의 공통 원인입니다.
**게이지에 보이는 숫자와 신뢰를 세는 숫자를 같은 것으로 취급하면 안 됩니다.**
