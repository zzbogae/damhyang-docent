## 1. 원칙 1 범위 수정 — 2026.09.27 보경 확정

### 기존 원칙 1
> 판정·해석·진단하지 않는다

### 수정 후
> **관측소(과거 데이터) 영역**에서 판정·해석·진단하지 않는다.
> **섬(미래 공간) 영역**에서 사용자가 건넨 단어를 연결·해석하는 것은 허용한다.
> 단, 그 해석이 과거 기록을 소급 판정하는 데 쓰이면 안 된다.

### 왜 다른가

관측소는 **이미 일어난 일**을 다룹니다. 여기서 AI가 「힘드셨겠어요」라고 말하면
사용자가 확인하거나 교정할 수 없는 판정이 됩니다. 그래서 막습니다.

섬은 **앞으로 만들어갈 공간**입니다. 사용자가 먼저 단어를 건넨 맥락에서
AI가 연결·해석하고, 사용자가 공감하면 섬이 열리고 공감하지 않으면 다시 고릅니다.
**틀려도 사용자가 교정할 수 있는 구조**라 장례식 오판과 층위가 다릅니다.

## 2. 3층 구조 확정

| 층 | 이름 | 무엇 | 누가 만드는가 |
|---|---|---|---|
| 1 | **지층** | 시간 축 — 주별 코어 | 파이프라인 (데이터가 정함) |
| 2 | **광석** | 코어에서 캔 것 — 광물·기록 | 파이프라인 (데이터가 정함) |
| 3 | **섬** | 사용자가 이름 붙인 미래 공간 | **사용자** (AI는 재료만 제공) |

지층과 광석은 관측소 원칙을 그대로 따릅니다 — 데이터가 정하고, AI가 판정하지 않습니다.
섬은 수정된 원칙 1을 따릅니다 — AI가 해석하되, 사용자가 최종 결정합니다.

## 3. 섬이 열리는 흐름

### 재료 출처 — 두 가지 병행

| 출처 | 방법 | 원칙 |
|---|---|---|
| 과거 데이터(메모·카톡·대화)에서 빈도 높은 단어 | 형태소 분석기 (`freq_scan.py`) | ✅ 집계. 판정 아님 |
| 민디와의 대화 중 사용자가 직접 입력한 단어 | 입력 그대로 | ✅ |

**AI가 하지 않는 것**: 「희망적이다」·「바람이다」·「고독을 원한다」같은 의미 분류.
**AI가 하는 것**: 사용자가 건넨 단어들을 받아 섬의 분위기·공간 요소로 연결.

### 민디 대화 흐름

```
민디   지금 떠오르는 것들을 골라보세요.

       (과거 기록에서 자주 나온 단어 칩)
       ┌─────────────────────────────────────
       │  구름   나무   벽   창문   새벽   책상
       └─────────────────────────────────────
       직접 쓰셔도 됩니다.

사용자  구름 · 나무 · 조용함

민디   (단어를 받아 섬의 분위기를 연결)
       이런 공간이 떠오릅니다.
       (공간 미리보기)

       이 공간에 이름을 붙이시겠어요?

사용자  안식처

       ─── 구름 속 섬이 하나 열립니다 ───
       (민디는 말하지 않습니다. 연출만.)
```

### 섬이 열린 후

나중에 닮은 맥락이 나왔을 때:
> 「안식처」라고 부르셨던 공간과 닮았습니다.

## 4. 단어→공간 변환 원칙

AI가 단어를 공간 요소로 연결할 때의 규칙입니다.

**허용 — 연결·배치**
- 「구름」→ 하늘 계열 배경·안개 레이어
- 「나무」→ 식물 컴포넌트
- 「벽」→ 닫힌 구조물·경계 요소
- 「새벽」→ 낮은 조도·블루 계열 조명

**금지 — 의미 판정**
- 「구름, 나무」→ 「자연 속 고독을 원함」
- 「새벽, 벽」→ 「고립감을 느끼는 사람」

연결은 되고 분류는 안 됩니다. 공간이 어떤 **느낌**인지는 사용자가 이름을 붙이면서 정합니다.

## 5. 섬 확장

**해커톤(10/3 발표)까지: 섬 하나**
이후 계획 — 두 가지 병행:

| 방식 | 조건 | 원칙 |
|---|---|---|
| 기록 누적으로 확장 | 새 광석이 일정 수 쌓이면 땅이 넓어짐 | ✅ 파이프라인 값 사용 |
| 과금 확장 | 출시 이후 고려 | 팀 회의 안건 (원칙 3 수정 필요) |

발표까지는 해당 없고, 출시 계획 수립 시 팀 회의에서 결정합니다.
