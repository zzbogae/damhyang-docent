# 팀 확정 규칙 반영(v8, 2026-10-03)

팀 HERIZON 9/23 차이 분석 문서(`260923_MineD_멘토보고_차이분석_요청_v1.md`)의 확정 사항과 요청을 이 저장소에 반영한 내역이다. 판정 결과 스키마는 `mined.week/8`(`schema/mined.week.v8.schema.json`), 바뀐 필드는 `docs/contract.md` 3절에 있다.

## 판정 지표 스위치(요청 4-1)

`DEFAULT_CONFIG["metric"]` 하나로 바꾼다. 나머지 단계(추세 보정 필터, 교차검증, 상관 병합, 확인 등급, 광물)는 두 지표가 같은 코드를 탄다.

- `mid_rank_pct`(기본): 직전 52주 중간 순위 백분위. 문턱은 꼬리 비율 `q_badge`, 방향별로 다르게 하려면 `q_dir`(아래)
- `robust_z`(팀 v6): `(x - 중앙값) / (1.4826·MAD)`, MAD 가 0 이면 평균절대편차 × 1.2533. 문턱은 축 × 방향 τ(`tau`, 없으면 팀 실측값 `TEAM_V6_TAU`)

robust z 는 언제나 함께 계산해 두므로(`P[지표]["z"]`) 지표를 바꿔도 결(줄무늬)과 4축 게이지의 `z` 는 같다.

### 실기록으로 비교하는 법

실제 기록 평가(`docs/field_eval.md`)의 전체 계산 보고서에 `configs.robust_z` 가 들어 있다. 받은 보고서를 모으면 두 번째 표가 지표 비교다.

```bash
core/.venv/bin/python core/scripts/field_collect.py 받은보고서/*.json -o out/field_eval_table.md
```

비교 항목은 팀이 적은 다섯 가지 그대로다: 사건 재현율(±1주), 사건에서 먼 주 판정률(오탐), 결측 가정 민감도(첫 번째 표의 `결측 가정 바꿔도 유지`), 배지 위/아래 수, 쓰인 광물 종 수. 명령줄에서 지표만 바꿔 판정하려면 `npm run cli -- <폴더> -o out --metric robust_z`.

### 합성 인물 기준값(인용 금지, 형태 확인용)

`field_collect.py --with-synth --full-synth` 결과. 합성 인물은 지표끼리 독립으로 만들어져 실기록과 분포가 다르다.

| 인물 | 지표 | 판정 주 | 먼 주 판정률 | 재현율 | 배지 위/아래 | 광물 종 | held / broken / not_returned |
|---|---|---|---|---|---|---|---|
| long(15년) | 백분위 | 87 | 8% | 79% | 161 / 73 | 9 | 21 / 65 / 0 |
| long | robust z | 123 | 12% | 79% | 205 / 125 | 8 | 0 / 46 / 74 |
| elder(8년) | 백분위 | 33 | 5% | 90% | 48 / 37 | 8 | 5 / 27 / 1 |
| elder | robust z | 25 | 3% | 100% | 34 / 32 | 5 | 0 / 14 / 11 |
| short(2년) | 백분위 | 9 | 0% | 67% | 19 / 11 | 5 | 4 / 5 / 0 |
| short | robust z | 22 | 14% | 100% | 46 / 29 | 6 | 0 / 3 / 18 |

- robust z 는 아래 방향 배지 비율이 높다(long 38% 대 백분위 31%). 팀의 「아래가 안 잡힌다」 문제가 백분위에도 약하게 있다는 신호다.
- robust z 에서 `held` 가 0인 것은 지표 때문이 아니라 「평소」 판정 규칙 때문이다. robust z 를 고르면 평소 = 같은 계열 지표가 모두 `|z| < 1`(팀 밴드)로 잡히는데, 4주 연속은 구조적으로 드물다(팀 §1-7 관찰과 같다). `tier_normal: "no_badge"` 로 두면 백분위와 같은 평소 규칙을 쓴다.

## 방향별 문턱(요청 4-2)

- 백분위: `q_dir = {"move": {"up": 0.03, "down": 0.05}, ...}` 처럼 축 × 방향으로 준다. 없는 축은 `q_badge`. `adaptive_q` 는 관측 지표 수에 맞춰 조인 비율(조인 q ÷ `q_badge`)을 방향별 q 에 똑같이 곱한다. `detrend` 는 배지 뒤에 거는 필터라 충돌하지 않는다.
- robust z: `tau` 가 곧 방향별 문턱이다.
- 아래 방향 배지를 줄이는 장치가 하나 더 있다: `zero_share_down_off = 0.5`(직전 창의 절반 넘게 0인 지표는 아래 배지를 끈다). 건수형 지표의 아래 방향을 볼 때 이 값도 같이 바꿔 볼 것.

## 확인 등급(요청 4-3·4-4)

`judge.grade_sequence()` 가 정한다. 판정된 주 `w` 뒤로:

1. `tier_horizon`(4)주 안의 첫 평소 주가 `return_week`
2. 그 뒤 `tier_run`(4)주(`hold_until` 까지)를 본다
   - 하나라도 평소 범위를 벗어나면 `broken`(확인은 됐고 유지가 안 됨)
   - 전부 평소면 `held`
   - 기록이 비었거나 아직 안 지났으면 `returned`
3. 돌아오지 않았는데 4주가 안 지났으면 `open`, 지났으면
   - 그 4주 중 관측된 주가 `tier_min_obs`(0.5) × 4 보다 적으면 `insufficient`
   - 아니면 `not_returned`

옛 v7 의 `passed` 는 「돌아오지 않음」과 「돌아왔다 다시 벗어남」을 한데 묶고 「확인되지 않았습니다」 문장을 붙였다. 팀 판단대로 이것은 사실과 달라서 둘을 나눴다. `not_returned` 는 팀 4등급에 없던 값이라 새로 붙였고, `broken` 과 함께 화면 문장을 비워 두었다(`GRADE_TEXT`). 문안이 정해지면 `judge.py` 의 `GRADE_TEXT` 와 `web/src/mindi/templates.ts` 의 `gradeText` 두 곳에 넣는다.

`insufficient` 기준 0.5 는 「4주 중 2주 이상 관측」이다. 합성 인물에서는 이 기준으로 `insufficient` 가 나오지 않았다(결측이 판정 주 바로 뒤에 몰리는 경우가 드묾). 실기록 평가에서 `grades.insufficient` 가 0이 아니면 그때 기준을 다시 본다.

## 광물 9종·결·축 이름

- 광물: 가장 강한 배지의 축 × 방향 8종. 배지가 3축 이상에 걸치면 형석(`complex_min_axes`). 팀 정의 「교차검증 = 형석」을 그대로 쓰면 이 코어는 배지 2개 이상이어야 판정하므로 판정 주 대부분(long 87주 중 83주)이 형석이 된다. 팀의 GEM_COMPLEX 정의를 받으면 `judge.mineral_shape()` 만 바꾼다.
- 결: 4축 각각의 `z`(축 안 게이지 지표 z 의 중앙값)가 밴드 `|z| < 1` 밖인 축 수. 합성 long 기준 mixed 22% · coarse 41% · regular 34%(팀 실측 17% · 37% · 46%).
- 축: `move/rest/watch/leave`, 화면 이름 걸음/쉼/화면/기록(`indicators.axis_screen`, `web/src/types.ts` 의 `axisScreen`).
- 색은 자리표시(`web/src/ui/minerals.ts`). 하빈 님 `gems.js` 를 병합하면 그 값으로 바꾼다.

## 고도화(2026-10-03 2차)

### 쉼 축 대체 지표: 밤 기록 공백

수면 기록이 없는 주가 많아(팀 실기록 커버리지 19%) 쉼 축이 비는 문제를 풀려고, 직접 남긴 활동(메모·보낸 카톡·유튜브·사진·DM·AI 대화)의 시각에서 **밤에 기록이 끊긴 가장 긴 시간**을 잰다(`web/src/import/quiet.ts`). 잠을 잰 값이 아니므로 화면에서도 「밤 기록 공백」이라고 부른다.

- 깨어난 날 D 에 붙인다. D-1 18:00 ~ D 14:00 의 활동 시각 사이 간격 중 가운데가 D-1 22:00 ~ D 09:00 인 가장 긴 것, 2~16시간만
- 계열 `quiet`, 지표 `quiet`(쉼 축). 다른 채널의 시각에서 계산한 값이라 **독립 근거 수에 넣지 않는다**(`DERIVED_FAMILIES`)
- 쉼 게이지는 수면 기록이 있으면 수면만, 없을 때만 밤 기록 공백을 쓴다(`axes.rest.via = "quiet"`, 화면에 「밤 기록 공백으로 봄」)
- **판정 배지에는 아직 쓰지 않는다**(`badge_off: ["quiet"]`). 합성 인물은 활동 시각이 수면과 무관하게 만들어져 있어 검증할 수 없다(순위 상관 0.02). 실기록 평가 보고서의 `quiet_vs_sleep`(수면 기록이 있는 주에서 두 값의 순위 상관)이 충분히 높게 나오면 `badge_off` 를 비운다

### 민디 자유 질문

「민디에게 직접 묻기」 입력칸. 기기 안 규칙(`web/src/mindi/intent.ts`)으로 문장을 정해진 질문에 잇는다. 외부 모델을 쓰지 않는다.

- 걸음·잠·화면·기록 × 많았던/적었던 8가지(광물 8종과 같은 칸)와 기존 7개 질문으로 연결하고, 「「…」로 알아들었습니다」를 함께 보여 준다
- 방향을 모르면(「메모 남긴 주」) 두 질문을 버튼으로 되묻는다
- 마음을 묻는 말(「그때 힘들었지?」)에는 「저는 그때의 마음이 어땠는지 판정하지 않습니다」로 답한다(원칙 1)
- 연결하지 못하면 지어내지 않고 「아직 답하지 못합니다」로 닫는다

### `insufficient` 기준 실측 → 기본값 1.0

`core/scripts/insufficient_sweep.py`: 합성 인물 long·elder 에 1~3주짜리 공백을 10·20·30% 넣고(씨앗 5개), 공백 없는 기록의 등급과 견줬다. 「돌아오지 않음」이라고 했는데 원래 기록에서는 돌아왔던 주를 거짓으로 센다.

| 기준(판정 창 4주 중 관측 비율) | insufficient | not_returned | 그중 거짓 |
|---|---|---|---|
| 0.25 | 18 (1.6%) | 52 | 42 |
| 0.5(이전 기본값) | 41 (3.7%) | 29 | 19 |
| 0.75 | 53 (4.8%) | 17 | 7 |
| **1.0(새 기본값)** | 62 (5.6%) | 8 | 1 |

4주가 모두 관측돼야 「돌아오지 않았다」고 말한다. 대가는 판정 주의 5.6% 가 「기록이 비어 판정할 수 없습니다」가 되는 것이다.

### 기록 더하기: 스크린타임 캡처·깃 커밋

가져오기 화면 아래 「기록 더하기」. 다시 가져오기를 해도 남고(`kv.extras`), 판정 직전에 일 단위 표에 합친다(`web/src/extras/extras.ts`).

- 스크린타임: 아이폰 「스크린 타임」·삼성 「디지털 웰빙」 캡처를 이 기기 안에서 읽는다. PP-OCRv5 글자 영역 검출 + 한국어 인식 모델(13MB, `npm run assets` 가 받는다). 「일일 평균」 아래 값은 그 주 하루 평균, 「오늘·어제」 값은 그날 값으로 넣는다. 앱별 줄은 쓰지 않는다. 날짜는 파일 이름에서 읽고 화면에서 고칠 수 있다. 이미지는 저장하지 않는다. 계열 `screen`, 지표 `screen_time`(화면 축)
- 흉내 낸 캡처 4장(아이폰 2·삼성 2)은 모두 정확히 읽었다(장당 0.2~0.8초, `e2e/ocr.spec.ts`). 실제 기기 캡처는 팀원 캡처로 다시 확인해야 한다
- 깃 커밋: 자기 저장소에서 `git log --author="$(git config user.email)" --date=iso-strict --pretty=format:%ad > mined_git.txt` 로 만든 파일. 커밋 메시지는 읽지 않고 날짜만 센다. 계열 `git`, 지표 `git_commits`(기록 축). GitHub API 는 외부 요청이라 쓰지 않는다

### 안드로이드 사진 공유

앱 설치 정보(`public/manifest.webmanifest`)에 공유 대상을 넣었다. 안드로이드 크롬에서 「홈 화면에 추가」한 뒤 갤러리에서 「공유 → Mine D」를 누르면, 서비스 워커가 사진을 받아 이 기기 캐시에 잠깐 두고 가져오기 화면으로 넘긴다. 서버로 가지 않는다(`e2e/offline.spec.ts` 가 응답이 서비스 워커에서 나왔는지 확인). 아이폰 사파리는 이 기능을 지원하지 않아 안내문에 「모두 선택」 방법을 적었다.
